# 阶段配置、最终查询和护栏修复

## 范围与验收

按用户批准的三批计划实施，沿用 minimal-diff：不改 NL2SQL 产品边界，不新增
Agent、DSL 或工具继承体系，不改投影/压缩算法，不修改业务库和旧运行记录。
每批修改与测试独立记录；不自动提交 Git。

第一批涉及 llm.py、两份评测清单及模型测试：决策 low thinking / 4096、回答
关闭 thinking / 2048、压缩关闭 thinking / 1024；决策和压缩用 JSON 输出。
实际请求、预留和日志共用阶段配置；输入水位保守预留最大的阶段输出空间。
length 且动作无法解析时直接 OutputBudgetExhausted，仅 stop 的非法动作可修复一次。

第二批涉及提示、ReAct/会话收尾、评测记录及测试：强调最终 SQL 的列、行、排序
及并列语义；合法选定的最终查询在回答失败或取消后仍可追溯，但不改变成功或 EX
口径，不自动修改模型 SQL。新增结果选择事件使用现有事件留档机制，不迁移表结构。

第三批涉及 sql_guard.py、tools.py 和测试：补 STR_POSITION 白名单；resource_limit
保持资源边界并提供缩小查询的正确反馈，不提示查 schema。

验收为离线 pytest、相关 Ruff/mypy，以及冻结配置后同一固定 20 题单次真实复跑、
独立官方 EX 评分。保留每题 14 次模型调用和 120 秒时限；不运行 500 题或业务九题。
按三批划分差异，不混入格式整理；新增运行可独立留档，撤销代码不需回滚旧数据库。
