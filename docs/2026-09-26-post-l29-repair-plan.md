SQLite 性能优化、多进程协调、账号权限、AgentScope 迁移不在范围内。必要的结果、事件与压缩来源持久化属于正确性修复，不以“暂不优化 SQLite”为由省略。业务数据库只读；测试使用临时数据库，禁止执行当前 `db.py` 的破坏性自测入口。

## 3. 最小设计调整

- [ ] 失败退路是保留原日志，仅在视图中省略完整已结束旧轮并记录范围，结果索引仍可恢复；关键任务信息仍放不下则停止。不得连续摘要直到模型恰好给出可接受文本。

验收：257447.69 被改为 1 必须拒绝；相同数字换了门店也拒绝；数字只出现在原 800 字截断点之后；二次摘要顺序；失效引用、并发过期来源、无收益、超预算、摘要超时；失败时原可见来源不被替换。强制小预算覆盖“更正口径、用户已确认、任务已完成”。

### F. BIRD Mini-Dev 适配与双轨回归（核心修复之后）

本批是后续评测准备，不把 benchmark 特例写进核心 Agent。经典 Mini-Dev 是 500 题、11 库；锁定 SQLite 版本及数据 revision，不混用含 CRUD 的扩展集。数据来源按官方指定的 canonical 数据集固定。[官方说明](https://github.com/bird-bench/mini_dev#overview)、[官方数据集](https://huggingface.co/datasets/birdsql/bird_mini_dev)

- [ ] 外部评测脚本按 db_id 注入只读连接与对应语义目录；复用原 Agent、细粒度工具及 SQL 护栏，不走绕开执行器的简化生成路径。可信代码可内省 schema 并加载官方字段说明；去除 llm.py 对 orders 和 business.db 的直接依赖，数据截止日由调用方按当前库提供。
- [ ] 固定 question＋evidence 设置；schema／字段说明可用，gold SQL 与评分结果不进入 Agent。不得用 gold 倒推指标库。新数据库没有人工指标定义时如实返回未定义，不套用 Jaffle Shop 的口径。暂不新增元数据平台或向量索引。
- [ ] 每题独立会话，回答动作明确指定 final_query_id，从已验证的查询取得最终 SQL；不能取最后一个探查查询或从自然语言回答里提取 SQL。不能形成有效最终 SQL 的题记录失败，不从统计分母移除。
- [ ] 区分送评的校验后 SQL 与受 200 行上限控制的工具预览 SQL，记录两者和完整性。官方评分器使用独立只读环境、执行时限和原始答案语义，不对预测／gold 随意追加展示 LIMIT。若两者不同，报告这是“完整答案 SQL 的 EX”，不是产品预览结果完整性的证明；不能默默放宽产品护栏来刷分。
- [ ] 固定官方评分脚本版本、题目顺序、预测数量和 SQL／db_id 映射；先做已知正确／错误／超时样例的评分器自检。主指标 EX 使用官方实现，不自行改成 SQL 字符串比较。[官方评分目录](https://github.com/bird-bench/mini_dev/tree/main/evaluation)
- [ ] 先固定一个覆盖多库的 20 题调试集验证适配，再冻结配置进行单次完整 500 题回归；记录调试题清单及人工调优历史，不能宣称开发集是未见测试集。运行前明确模型、最大调用数、单题总时限、token 与总费用上限，达到上限停止并报告未完成题，不做无界重跑。

另保留业务九题：固定业务库快照、Asia/Shanghai 时钟为 2026-09-24，核对题目是否与原基线完全一致；正常九题与强制压缩轨迹分别运行。固定时钟必须覆盖提示日期与 SQL 中的相对时间，不能只替换 date.today 而让 CURRENT_DATE／date('now') 继续使用机器时钟；测试需明确验证该边界，未对齐时不可直接比较 90 天数值。结果包括 SQL 数值正确性、证据引用、工具／重复查询次数、输入成本、延迟、终态、压缩收益与保真。Mini-Dev 单题 EX 不能证明多轮上下文或语义层创新有效。
